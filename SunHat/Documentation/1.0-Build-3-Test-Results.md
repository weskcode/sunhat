## Issues Found and Fixed During This Review

The following issues were identified in the test files and corrected before running:

### DashboardViewTests.swift
1. **`LocationData` init mismatch** - Tests used `LocationData(name:latitude:longitude:)` but source init is `LocationData(latitude:longitude:city:)`. Fixed all 5 occurrences.
2. **Property name mismatch** - Tests referenced `.name` on `LocationData` but the property is `.city`. Fixed to use `.city`.
3. **`UserPreferences.temperatureUnit` type mismatch** - Test assigned `"fahrenheit"` (String) but the property is `TemperatureUnit` enum. Fixed to use `.fahrenheit`.
4. **`WeatherAlert` is a struct, not a `@Model`** - Test tried to use `WeatherAlert()` no-arg init, set properties, and insert into `modelContext`. WeatherAlert is a plain struct with required init parameters (`title:description:severity:`), not a SwiftData model. Rewrote test to validate struct creation without persistence.
5. **`WeatherAlert` property names** - Test used `alertDescription`, `startTime`, `endTime`, and `location` which don't exist. Correct properties are `description`, `timestamp`, `expiresAt`.
6. **`XCTAssertEqual` accuracy overload** - Optional `Double?` from `locations.first?.latitude` cannot be used with the `accuracy:` parameter variant. Fixed by force-unwrapping after count assertion.
7. **Missing models in SwiftData schema** - Added `TriggerCondition.self`, `NotificationConfig.self`, and `ReminderHistory.self` to the schema to ensure all model relationships are properly registered.

### WeatherServiceTests.swift
8. **Incomplete SwiftData schema** - Added `WeatherReminder.self`, `TriggerCondition.self`, `NotificationConfig.self`, `ReminderHistory.self`, and `UserPreferences.self` to ensure full model graph registration.

### DashboardUITests.swift
9. **`XCUIElementQuery` vs `XCUIElement`** - `app.otherElements.containing(...)` returns an `XCUIElementQuery`, not an `XCUIElement`, so `.exists` was unavailable. Fixed by appending `.firstMatch`.
10. **Splash screen timing** - Added `waitForExistence(timeout: 5)` in `setUpWithError()` to account for the new splash screen animation (1.9s) before interacting with tab bar elements.
